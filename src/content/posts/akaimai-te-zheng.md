### 2. 航空站点最致命的几道坎（必须全部过）

| 检测点 | 航空站点阈值 | 常见翻车原因 | 必须做法 |
| --- | --- | --- | --- |
| sensor_data 完整性 | 99.9% | 少了哪怕 1 个字段或顺序错 | 100% 复现原 JS 逻辑，不能手写 |
| Canvas/WebGL 指纹 | 真实设备级 | 虚拟机/云手机几乎秒挂 | 必须用真实 Windows/Mac 设备采集 |
| 鼠标/触摸轨迹 | 人类级自然度 | 直线、匀速、固定间隔全挂 | 贝塞尔曲线 + 随机扰动 + 人类停顿 |
| TLS/JA3/JA3S 指纹 | 严格匹配 | Python requests、curl 原生全挂 | 必须用 uTLS + 真实 Chrome 对应版本 |
| akamai-bm-telemetry | 必须携带 | 很多工具直接漏掉这个 Header | 必须完整生成并放入 Header |
| Cookie 时效 & 刷新 | 极短 | ABCK 过期 5-10 分钟就失效 | 每 3-5 分钟强制刷新一次 Cookie |

### 4. 航空站点封禁特征（秒懂你挂没挂）

| 响应特征 | 含义 |
| --- | --- |
| 200 + 页面出现验证码滑块 | 轻度怀疑 |
| 200 + 页面空白/无限 loading | 中度风控（sensor_data 错） |
| 403 + "Access Denied" | 重度，IP/指纹全黑 |
| 302 跳转到 /block 或 /challenge | 彻底挂了，换 IP + 设备 |

### 5. 2025 年最新趋势（航空专属）

1. Akamai 开始对“轨迹相似度”做聚类分析 → 100 个账号轨迹太像 = 集体封禁
2. 新增“订票行为模型”：搜票 → 选航班 → 填乘客 → 支付，整个链路不自然直接挂
3. UA/DL 试点“设备绑定”：同一设备指纹 24h 内出票超过 5 张 = 永封

总结：2025 年想稳定刷航空票，纯 requests 基本宣告死亡，必须走到“真实浏览器 + 实时解密”或者“全链路 Playwright”的路线。成本比 2023 年高 5-10 倍，但成功率也从 30% 提升到 90%+。
